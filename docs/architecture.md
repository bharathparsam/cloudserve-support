# CloudServe Support architecture

The product is a local Python support-processing pipeline. `evaluation.harness` accepts an input path and output directory, processes every record unattended, and writes outcomes, decision logs and calculated reports. FastAPI serves a small HTML/CSS/JavaScript dashboard alongside the programmatic interface and generated API documentation. The dashboard has no Node dependency or build step.

Both entry points use the same LangGraph workflow: normalize four-channel input, classify intent/urgency, retrieve ranked MiniLM/Chroma passages, assess sensitivity, route deterministically, draft cited claims, validate, and commit an answer or handoff. Private information, instruction overrides, unsupported claims, irrelevant answers, insufficient confidence and provider failures block automatic release. The optional Decider experiment was removed; semantic validation remains part of the required pipeline.

SQLite persists input sidecars, events, jobs, outcomes, releases, reviews, model cache and control epochs. Labels, customer groups and historical outcomes are evaluation-only sidecars. Predictive/provider payloads contain sanitized subject/body and relevant source passages. Every decision is linked to requirement IDs, source/model fingerprints and prompt versions. Missing closure or human reviews produces unavailable metrics, not invented business results.

Operator stop is an immediate durable epoch change, available by Python command or authenticated API. Release rechecks the epoch in the transaction that writes the outcome and audit evidence. Stop/re-enable cannot release an old draft; audit failure prevents release. The API worker claims only API-owned jobs. CLI batches hold the shared processing lock and use separate physical Chroma indexes from the same immutable assets, so processes do not share writable native index files.

A separate lightweight Python metrics server reads the same persistent store on port 8001. It stays alive after a batch exits. Prometheus scrapes every 15 seconds; Grafana displays the provisioned throughput, answer/escalation, latency, guardrail and confidence panels. Docker Compose runs only these two monitoring services. FastAPI binds to localhost at port 8000; mutations and original-input access require a local bearer token. This is a local application, not a production identity or tenancy system.

The dashboard loads JSON datasets, submits background runs, displays persisted stage accounting and ticket outcomes, and offers an authenticated model-settings pane. Its model list is restricted to Gemma 4 26B Free, Llama 3.1 8B Free, GPT-4.1 and GPT-4.1 Mini. Paid uploads require per-run consent bound to the selected model; admission is audited in the run transaction and retains the shared paid-budget ledger. Browser access uses the local operator token in page memory. The app does not expose the OpenRouter key to the browser.

Fresh model configuration is free-only. Legacy disabled-observer fields remain readable for audit compatibility; active observer modes are rejected. Historical paid adapters retain durable cost reservations, known-charge accounting, an authorized cap and explicit evaluation gates. Ordinary free setup never selects paid mode or resets old records. Historical paid runs and pre-simplification test results remain evidence for their recorded source revisions, not proof of acceptance of this build.

The submitted repository retains pinned dependencies, versioned prompts, tests, CI, evaluation/analysis and architecture/operations documentation. Original capstone documents govern the scope. Report, five workbooks, effort log, actual human review and video remain separate submission deliverables.
